## 골든패스 시나리오 (목표: 5분 이내)

### Step 1 — 가입 (목표: 90초)

1. 홈 페이지 진입 → "회원가입" 버튼
2. 입력:
   - 이메일 `test+persona@easystock.com`
   - 비밀번호 `TestPassword123`
   - 가게이름 `김지영빙수`
   - 가게유형 `빙수카페`
   - 정기휴무 요일 `월요일` 체크
3. 쿠키 동의 배너에서 "동의"
4. "가입하기" → 자동 로그인
5. **검증**: 오늘(홈) 화면 진입, 상단에 "데이터 수집 중" 콜드스타트 안내

**자동화 측정**: GA4 이벤트 `signup_complete` 발송 확인

---

### Step 2 — 메뉴 템플릿 불러오기 (목표: 60초)

1. 하단 탭 "메뉴" 진입
2. "빙수카페 템플릿 불러오기 (8종)" 버튼 클릭
3. **검증**:
   - 메뉴 8개 자동 등록 (딸기빙수, 인절미빙수, ...)
   - 각 메뉴에 레시피 항목 포함
   - 재료 ~15개 자동 등록 (이름 unique 충돌 없음)
   - 모든 메뉴의 마진율은 일단 100% (재료 단가 0원, 매입 전이라 정상)
   - "재료 원가 기준 (이동평균법)" 라벨 모든 마진 표시 지점에 노출

**자동화 측정**: GA4 이벤트 `first_menu_registered`

---

### Step 3 — 매입 1건 등록 (목표: 90초)

페르소나가 거래명세서 받았다고 가정.

1. 하단 탭 "재료" → 우상단 "+ 매입 등록" (또는 빠른 액션)
2. 거래처 추가: "동네과일" / 리드타임 1일
3. 매입 항목:
   - 딸기 2kg / 24,000원
   - 우유 5L / 7,500원
   - 연유 1kg / 10,000원
4. "저장" 클릭
5. **검증**:
   - 재료별 평균 단가 갱신 (딸기 12,000원/kg = 12원/g)
   - 재고 증가 (딸기 2000g, 우유 5000ml, 연유 1000g)
   - IngredientPriceHistory 3건 추가
   - 첫 매입이라 변동 알림 없음 (FR-005 조건 미해당)
   - 메뉴 화면 다시 들어가면 마진율 계산값 정상 표시 (예: 딸기빙수 77% 등)

---

### Step 4 — 첫 판매 입력 (목표: 90초) ★ MVP 첫 검증 지점

1. 하단 탭 "판매" 진입
2. 자주 팔리는 메뉴 정렬은 7일 데이터 부족 → 등록 순 정렬 fallback
3. 판매량 입력 (페르소나의 평일 약 35만원 가정):
   - 아메리카노 +32
   - 카페라떼 +18
   - 딸기빙수 +8
   - 인절미빙수 +12
   - 망고빙수 +3
4. **실시간 검증** (각 입력마다):
   - 매출 합계 갱신
   - 재료 원가 갱신 (이동평균법)
   - 순수익 갱신
   - "재료 원가 기준 (이동평균법)" 라벨 항상 노출
   - 응답 100ms 이내 (Performance 목표)
5. 0잔 메뉴는 자동 숨김 (FR-010)
6. "저장하기" 클릭
7. **검증**:
   - Sale 레코드 + items 저장 (각 항목에 menu_cost_snapshot 보존)
   - 재료 자동 차감 (FR-008)
   - 푸시 권한 요청 모달 노출 (R1 — 첫 가치 경험 직후)
   - GA4 `first_sale_input` 이벤트

**자동화 측정**: 가입 시작부터 이 시점까지 < 5분 (SC-001)

---

### Step 5 — 마진 확인 (목표: 30초)

1. 하단 탭 "오늘" 진입
2. **검증**:
   - 어제(오늘 입력했지만 어제 날짜로 입력했다면) 매출/순수익/마진율 카드
   - "재료 원가 기준 (이동평균법)" 라벨
   - "지난주 같은 요일 대비" 비교는 첫날이라 비활성 또는 N/A
   - 메뉴별 마진 TOP3 카드 (이 단계에선 모든 메뉴 1번씩만 팔렸으므로 단순 마진 순위)

---

## 골든패스 통과 기준

| 항목 | 기준 | 측정 |
|---|---|---|
| 총 소요 시간 | ≤ 5분 | E2E 테스트 시작~종료 timing |
| FR-019 라벨 누락 | 0건 | DOM 스캔 (모든 마진 표시 지점에 텍스트 존재) |
| 가중 평균 정확도 | ±0.01원 | 수동 계산값과 비교 (SC-009) |
| 재고 차감 정확도 | 100% | 레시피 × quantity 정확히 차감 |
| 메뉴 원가 스냅샷 | Sale 레코드에 보존 | DB 쿼리로 sale_items.menu_cost_snapshot NOT NULL |

## 회귀 시나리오 (스토리별 추가 검증)

골든패스 외에 각 user story의 핵심 경로는 별도 통합 테스트로 검증:

| Story | 추가 검증 |
|---|---|
| US1 sale | 7일 이내 소급 입력 가능 / 7일 초과 차단 / 편집 시 새 스냅샷 |
| US2 purchase | ±5% 변동 알림 / 첫 매입 (재고 0) 케이스 / 변동 이력 기록 |
| US3 menu | 매입 후 마진 자동 재계산 / 단가 ±5% 변동 표시 |
| US4 inventory | 콜드스타트 안내 / 7일+ 데이터 후 예측 활성화 / 정기휴무 제외 평균 / 실사 후 단가 불변 |
| US5 dashboard | 어제 미입력 빨간 배지 / 메뉴 마진 TOP3 / 마진 낮은 메뉴 원인 표시 |
| US6 calendar | 셀 인텐시티 + 도트 / 누락일 탭 → 소급 입력 / 정기휴무 회색 / 미래·가입전 회색 |
