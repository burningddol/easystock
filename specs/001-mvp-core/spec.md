# Feature Specification: MVP 핵심 — 6개 화면 통합

**Feature Branch**: `001-mvp-core`
**Created**: 2026-04-30
**Status**: Draft
**Input**: 카페/빙수 자영업자(페르소나: 김지영, 34세, 빙수카페 2년차)가 매일 입력하는 매입·판매 데이터를 받아 메뉴별 실시간 마진과 재료 소진 예측을 자동으로 보여주는 모바일·PWA 서비스의 1차 MVP. 6개 화면(판매/매입/메뉴/재료/오늘/캘린더)을 하단 탭 5개와 컨텍스트 진입(매입)으로 구성. 핵심 가설: "어차피 엑셀에 입력하던 것을 우리에게 입력하면 알아서 다 보여줌."

## Clarifications

### Session 2026-04-30

- Q: Sale 레코드 저장 후 편집·삭제 정책 → A: 7일 이내 편집·삭제 가능 + 변경 이력 보존 + 편집 시 새 메뉴 원가 스냅샷으로 재계산. 7일 초과 시 잠금. (Option C — 소급 입력 7일 정책과 정합, 헌법 III "역사적 마진 보존"은 시간 경과에 따른 자동 재계산 금지를 의미하지 사용자 명시 편집까지 막지는 않음)
- Q: 회원 탈퇴·계정 삭제 시 데이터 처리 → A: 30일 grace period 적용. 탈퇴 신청 후 30일간 복구 가능, 이 기간 동안 데이터는 보존되되 로그인 차단. 30일 경과 시 모든 데이터 영구 삭제 (PIPA 표준). (Option B — 사고성 탈퇴 보호 + 누적 데이터 손실 방지)
- Q: 메뉴·재료·거래처 이름 중복 허용 여부 → A: 사용자 단위로 이름 unique. 활성·비활성 무관 중복 차단. 시즌별 변형은 명칭에 시즌 표기로 회피 (예: "딸기빙수 2026"). (Option A — MVP 단순함 우선, 데이터 무결성)
- Q: Multi-device 동시 사용 시 데이터 동기화 정책 → A: 동시 편집 가정 안 함, last-write-wins. 충돌 감지·해결 없음, 마지막 저장이 우선. Realtime 구독은 1차 MVP에서 제외. (Option A — 페르소나 단일 디바이스 가정, 인프라 단순화)
- Q: 데이터 export 기능 1차 MVP 포함 여부 → A: 미지원. Out of Scope에 명시 추가. (Option A — 입력 마찰 줄이기 우선, export는 데이터 누적 후 2차 가치 발생. 회원 탈퇴 grace period로 데이터 통제권은 일부 보장)
- Q: 정기휴무·휴업 처리 정책 (페르소나 가정: 정기휴무 주 1회) → A: 가게 정보에 정기휴무 요일 등록(복수 가능). 시스템이 누락 카운트·푸시·소진 예측 평균에서 자동 제외. 캘린더는 정기휴무일을 회색 비활성으로 표시. 일회성 휴업(명절·휴가)은 1차 MVP 미지원 — 빨간 점 표시 수용. (Option A — 셋업 시 1회 등록으로 영구 효과, 입력 마찰 최소)

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 마감 후 판매 일괄 입력 (Priority: P1)

사장님이 마감 후 5분 안에 그날 메뉴별 판매량을 입력하고 즉시 재료 원가 기준 마진을 확인한다. 자주 팔리는 메뉴는 자동 정렬되고, +/- 버튼 또는 직접 입력으로 빠르게 수량을 조정한다. 0잔 메뉴는 자동 숨김 처리되어 시야가 정리된다. 입력 도중 매출/원가/순수익이 실시간으로 갱신된다.

**Why this priority**: 매일 발생하는 핵심 행동이며 입력이 끊기면 모든 가치(마진/예측)가 무너진다. 페르소나 사용 빈도 1순위.

**Independent Test**: 메뉴/레시피가 미리 등록된 사용자가 판매 화면에 진입해 메뉴별 수량을 입력하면 시스템이 매출/재료원가/순수익을 즉시 표시하고, 저장 시 재료가 자동 차감된다.

**Acceptance Scenarios**:

1. **Given** 활성 메뉴와 레시피가 등록된 상태, **When** +/- 버튼 또는 직접 입력으로 메뉴별 수량을 입력, **Then** 매출/원가/순수익이 실시간 갱신되며 "재료 원가 기준 (이동평균법)" 라벨이 함께 노출된다
2. **Given** 사용자가 판매 화면 진입, **When** 화면 표시, **Then** 지난 7일 판매량 기준 상위 메뉴가 위쪽에 자동 정렬된다
3. **Given** 0잔 입력된 메뉴, **When** 화면 표시, **Then** 해당 메뉴 행은 자동 숨김
4. **Given** 어제 판매가 미입력 상태, **When** 사용자가 어제 날짜를 선택, **Then** 7일 이내 소급 입력 가능 (7일 초과 날짜는 차단)
5. **Given** 판매 저장 실행, **When** 저장 완료, **Then** 레시피대로 재료 자동 차감 + 판매 시점 메뉴 원가가 판매 레코드에 스냅샷으로 저장된다 (역사적 마진 보존)

### User Story 2 — 거래명세서 받고 매입 입력 (Priority: P2)

사장님이 거래처에서 재료를 받은 직후 거래처/날짜/재료/수량/금액을 직접 입력한다. 신규 거래처나 신규 재료도 입력 흐름 안에서 즉시 추가 가능하다. 이전 매입 단가와 비교하여 변동이 큰 경우 즉시 표시된다.

**Why this priority**: 매입이 입력되어야 평균 단가가 갱신되고 마진이 정확해진다. 거래명세서 받을 때(주 1~2회)만 발생하므로 매일 사용보다 빈도는 낮으며, 하단 탭이 아닌 컨텍스트 진입(예: 재료 화면 또는 빠른 액션)으로 처리한다.

**Independent Test**: 매입 입력 화면에서 거래처/재료/수량/금액을 입력하고 저장하면 해당 재료의 평균 단가가 가중 이동 평균법으로 갱신되고, 재고량이 증가하며, 단가 변동 이력이 기록된다.

**Acceptance Scenarios**:

1. **Given** 거래처와 재료가 미리 등록되어 있거나 입력 흐름에서 신규 추가 가능, **When** 매입 항목 입력 후 저장, **Then** 가중 이동 평균법으로 재료별 평균 단가 갱신: `새 평균 = (현재 재고 × 현재 평균 + 신규 수량 × 신규 단가) ÷ (현재 재고 + 신규 수량)`
2. **Given** 같은 재료의 이전 매입 단가가 존재, **When** 신규 매입 입력, **Then** 직전 평균 단가 대비 ±5% 이상 차이 시 변동 알림 표시
3. **Given** 첫 매입 (이전 재고 0), **When** 매입 저장, **Then** 신규 단가가 그대로 평균 단가로 설정됨
4. **Given** 매입 저장 완료, **When** 후처리, **Then** 재고량 증가 + 평균 단가 갱신 이력 기록 (직전 평균 → 신규 평균 + 변경 사유 = "매입")

### User Story 3 — 메뉴/레시피 등록 및 단가 추적 (Priority: P3)

사장님이 메뉴와 그 레시피(재료별 사용량)를 등록한다. 신규 가입자는 가게유형별 템플릿(빙수카페 8종, 카페 음료 10종)을 한 번에 불러와 시작할 수 있다. 등록된 메뉴는 매입 단가 변동에 따라 마진이 자동 재계산되며, 단가가 크게 흔들린 메뉴는 변동 표시로 즉시 인지된다.

**Why this priority**: 셋업 시 1회 + 가격 변동 시 수정. 사용 빈도는 낮지만 마진 계산의 기반이라 P1(판매 입력)이 의미 있게 동작하기 위한 전제다.

**Independent Test**: 신규 사용자가 메뉴 화면에서 빙수카페 템플릿을 불러오면 메뉴 8개와 각 레시피가 등록된다. 한 메뉴를 선택하면 재료별 평균 단가, 메뉴원가, 마진율이 표시된다.

**Acceptance Scenarios**:

1. **Given** 신규 가입 사용자, **When** 메뉴 화면 첫 진입, **Then** 가게유형별 템플릿(빙수카페 8종, 카페 음료 10종) 불러오기 옵션이 노출된다
2. **Given** 메뉴 선택, **When** 상세 화면 표시, **Then** 레시피(재료 + 사용량) + 재료별 현재 평균 단가 + 메뉴원가 + 마진율이 "재료 원가 기준 (이동평균법)" 라벨과 함께 표시된다
3. **Given** 매입으로 재료 단가가 변동, **When** 메뉴 다음 조회, **Then** 메뉴 마진이 자동 재계산되어 갱신된 값으로 표시
4. **Given** 단가가 직전 대비 ±5% 이상 변동, **When** 메뉴 표시, **Then** "딸기 단가 +X%" 식의 변동 표시 노출

### User Story 4 — 재료 소진 예측 및 발주 알림 (Priority: P4)

사장님이 재료 화면에서 어떤 재료가 언제 소진되는지 한눈에 보고, 발주가 필요한 항목은 푸시 알림으로 받는다. 매주 월요일 오픈 전 재고 실사 알림으로 시스템 재고와 실재고의 차이를 보정한다.

**Why this priority**: "발주 까먹어서 영업 중에 마트 뛰어가는" 페르소나 페인을 직접 해소하는 핵심 가치 제공 지점이다. 다만 데이터가 누적되어야 정확하므로 가입 직후에는 가치가 작다.

**Independent Test**: 7일 이상의 판매 데이터가 누적된 사용자가 재료 화면에 진입하면 각 재료의 예상 소진일이 표시되고 상태(안전/주의/발주/소진)로 분류된다. 발주 필요 상태에서 아침 9시에 푸시 알림이 발송된다.

**Acceptance Scenarios**:

1. **Given** 7일 이상 판매 데이터, **When** 재료 화면 진입, **Then** 영업일 그룹(월~목/금/주말) 최근가중 평균 + 개별요일 shrinkage 보정 + 거래처 리드타임 + 안전여유 1일을 반영한 소진 예상일 표시
2. **Given** 가입 후 7일 이내, **When** 재료 화면 표시, **Then** "데이터 수집 중, 정확한 예측은 다음 주부터" 콜드스타트 안내
3. **Given** 재료가 발주 필요 상태(소진 예상 1~2일 전), **When** 아침 9시 도래, **Then** 푸시 알림 발송 (예: "딸기 2일 후 소진 예상 → 발주하기")
4. **Given** 매주 월요일 오픈 전, **When** 정해진 시각 도래, **Then** 재고 실사 알림 푸시 발송
5. **Given** 사용자가 재고 실사 입력, **When** 시스템 재고와 실재고에 차이 존재, **Then** 차이를 "주간 손실액"으로 환산해 표시. 평균 단가는 변경되지 않음 (수량 보정만)
6. **Given** 사용 패턴 급증/급감 (7일 평균 vs 30일 평균 차이 ±20% 이상), **When** 재료 표시, **Then** "최근 사용량 급증 중" 또는 "급감 중" 배지
7. **Given** 예측 데이터가 표시됨, **When** 재료·메뉴 예측 화면 진입, **Then** 예측 신뢰도(높음/보통/낮음/수집 중)와 데이터 일수·요일 보정 비율을 함께 표시
8. **Given** 발주 추천량이 표시됨, **When** 재료 카드 확인, **Then** 권장 수량, 발주 기한, 리드타임, 안전여유, 목표 운영일 기준을 함께 표시
9. **Given** 재료 예측 정확도 백테스트가 가능한 상태, **When** 재료 카드 확인, **Then** 평균 일수오차를 “보통 ±N일”로 표시하고 예상 소진일에서 오차를 차감한 “빠르면 N일” 위험 힌트를 함께 표시

### User Story 5 — 홈 대시보드 (오늘) (Priority: P5)

사장님이 아침 오픈 전 1분 안에 "오늘 뭘 해야 하는가"를 확인한다. 화면 최상단에 액션 알림(소진/유통기한), 그 아래 어제 KPI(매출/순수익/마진율), 메뉴별 마진 TOP3와 마진 낮은 메뉴의 원인이 표시된다.

**Why this priority**: 다른 화면의 데이터를 모아 보여주는 viewer로, 데이터가 쌓인 후 가치가 발생한다. 매일 1분 체크 흐름의 진입점.

**Independent Test**: 어제 판매·매입·재고 데이터가 있는 사용자가 오늘 탭 진입 시 알림/어제 KPI/메뉴 마진 TOP3가 한 화면에 표시된다.

**Acceptance Scenarios**:

1. **Given** 오늘 탭 진입, **When** 화면 표시, **Then** 최상단에 "오늘의 알림" (소진 예상, 유통기한 임박 등 액션 아이템 우선)
2. **Given** 어제 판매 입력 완료, **When** 화면 표시, **Then** 어제 매출/순수익/마진율이 "재료 원가 기준 (이동평균법)" 라벨 + 지난주 같은 요일 대비 변화율과 함께 표시
3. **Given** 이번 주 판매 데이터, **When** 화면 표시, **Then** 메뉴별 마진 TOP3 + 마진 낮은 메뉴 원인 표시 (예: "딸기빙수 18% — 딸기값 인상 영향")
4. **Given** 어제 판매 미입력, **When** 화면 표시, **Then** 빨간 배지로 "어제 판매 입력 필요" 알림

### User Story 6 — 월간 캘린더 (월간 장부) (Priority: P6)

사장님이 한 달간의 매출 패턴, 매입한 날, 입력 누락한 날을 한 화면에서 보고, 누락일 셀을 탭해 즉시 소급 입력한다. 셀 인텐시티(매출 히트맵)와 도트(매입/누락)로 30일을 한 화면에 압축한다. 임의 날짜 선택 시 하단에 선택일 상세가 표시된다.

**Why this priority**: 월간 시각화는 데이터가 한 달 이상 누적되어야 가치가 발생한다. 입력 누락 발견 → 즉시 소급 입력 동선이 일일 입력률 60% 목표에 직접 기여하므로 P6라도 출시 범위에 포함한다.

**Independent Test**: 한 달 분량의 판매/매입 데이터가 있는 사용자가 캘린더 탭 진입 시 30일 셀이 매출 인텐시티 + 매입(앰버)/누락(레드) 도트로 표시되고, 누락일 셀을 탭하면 해당 날짜 판매 입력 화면으로 이동한다.

**Acceptance Scenarios**:

1. **Given** 캘린더 탭 진입, **When** 화면 표시, **Then** 월간 누적 카드(매출/순수익/일평균/영업일수)와 7×6 캘린더 그리드가 노출되며, 순수익은 "재료 원가 기준 (이동평균법)" 라벨과 함께 표시
2. **Given** 캘린더 셀에 그날 데이터 존재, **When** 셀 표시, **Then** 다음 시각 코딩이 적용된다 — 배경 인텐시티 = 매출 히트맵 / 우상 앰버 도트 = 매입 있는 날 / 우상 레드 도트 = 입력 누락일 / 좌하 = 매출 만원 단위 숫자
3. **Given** 누락일 셀(레드 도트), **When** 사용자가 탭, **Then** 해당 날짜의 판매 입력 화면으로 이동 (소급 입력 모드, 7일 이내일 때)
4. **Given** 7일 초과 누락일, **When** 사용자가 탭, **Then** "이미 만료" 안내, 입력 불가
5. **Given** 미래 날짜 셀, **When** 사용자가 탭, **Then** 입력 불가 안내
6. **Given** 가입일 이전 날짜 셀 또는 정기휴무 요일 셀, **When** 화면 표시, **Then** 회색 비활성 처리 (단, 정기휴무 요일에 판매가 입력된 경우는 정상 셀)
7. **Given** 임의 날짜 선택, **When** 셀 탭, **Then** 화면 하단에 선택일 상세 (매출/매입/베스트셀러)
8. **Given** 누락이 2일 이상 연속, **When** 캘린더 표시, **Then** 강조 색상으로 시각적 경고 (디자인 시스템의 "누락" 라벨)
9. **Given** 미래 날짜 셀, **When** 상세 화면 진입, **Then** 예상 매출 범위(예: 92만~108만원), 메뉴 소요량, 예측 신뢰도·근거를 표시
10. **Given** 최근 과거 날짜 셀, **When** 백테스트 가능한 판매 이력이 존재, **Then** 당시 예측 판매량과 실제 판매량, 평균 수량오차, 매출 signed error(높게/낮게 예측), 평균 금액오차를 비교 표시

### Edge Cases

- **콜드스타트 (가입 후 7일 이내)**: 모든 화면에 "데이터 수집 중" 안내, 소진 예측은 가동하지 않음
- **레시피 미등록 메뉴 판매 입력 시도**: 입력 차단 + 메뉴/레시피 등록 유도
- **재고가 음수가 되는 경우**: 0으로 보정 + 경고 표시 (재료 화면)
- **단가 변동 ±5% 이상**: 매입·메뉴 화면에서 변동 표시
- **거래처 리드타임 미설정**: 기본값 1일 적용
- **iOS 16.3 이하 사용자**: PWA 푸시 미지원 안내, 인앱 알림으로 대체
- **소급 입력 7일 초과**: 차단, 캘린더에서도 "이미 만료" 표시
- **매입 입력 후 취소·환불**: 1차 MVP에서 직접 취소 불가. 정정 매입(음수 수량 또는 보정 매입)으로만 보정
- **재고 실사로 평균 단가 영향 여부**: 영향 없음. 실사는 수량만 보정, 평균 단가는 매입에서만 변경
- **메뉴별 옵션·토핑**: 메뉴 옵션 그룹으로 등록한다. 택1 옵션은 선택률 합계를 1로 정규화하고, 선택률 데이터가 없으면 기본 옵션을 fallback으로 사용한다. 추가 옵션은 attach-rate 방식으로 재료 소요량에 반영한다
- **미래 날짜로 입력 시도**: 차단
- **푸시 알림 권한 거부 사용자**: 인앱 알림(상단 배너 + 캘린더 도트)으로 대체
- **7일 초과 Sale 편집 시도**: 잠금 안내 표시, 편집 불가 (정정 거래로만 보정 가능)
- **Sale 편집으로 재고가 음수가 되는 경우**: 차단 + 안내 (재료 부족 표시)
- **Grace period 중 로그인 시도**: 차단 + 복구 안내 + 영구 삭제 예정일 표시
- **Grace period 중 같은 이메일로 신규 가입 시도**: 차단 + 기존 계정 복구 안내
- **이름 중복 등록 시도 (메뉴·재료·거래처)**: 차단 + 기존 항목 안내. 시즌별 변형은 명칭 변경(예: "딸기빙수 2026") 안내
- **정기휴무 요일에 영업 (예외 영업)**: 사용자가 그날 판매 입력 시 정상 영업일로 인식 (캘린더 회색 → 일반 셀로 전환, 누락 카운트·예측 산정에 포함)
- **정기휴무 요일 변경 시 과거 데이터**: 변경 이후부터 새 규칙 적용. 과거 셀 표시는 그 시점의 규칙 유지 (snapshot)
- **일회성 휴업 (명절·휴가)**: 1차 MVP 미지원. 빨간 점 표시 수용 — 사장님 인지로 무시 가능 (연 5~10일 수준 가정)
- **분석 도구 쿠키 동의 (PIPA)**: 신규 가입자 첫 진입 시 GA4 등 분석 쿠키 동의 배너 노출. 거부 시 분석 추적 비활성, 서비스 이용은 정상 (분석만 미작동). 동의 상태는 사용자 단위로 저장

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 사장님은 회원가입 후 가게 정보(이름, 가게유형)를 등록할 수 있어야 한다
- **FR-002**: 시스템은 모든 사용자 데이터를 사용자 단위로 격리해야 한다 — 한 사용자는 다른 사용자의 데이터에 접근할 수 없다
- **FR-003**: 시스템은 메뉴 등록 시 가게유형별 템플릿(빙수카페 8종, 카페 음료 10종)을 일괄 불러오기 옵션으로 제공해야 한다
- **FR-004**: 재료 단가는 가중 이동 평균법으로 산정한다. 매입 시 새 평균 = (현재 재고 × 현재 평균 + 신규 수량 × 신규 단가) ÷ (현재 재고 + 신규 수량)
- **FR-005**: 매입 입력 시 직전 평균 단가 대비 ±5% 이상 차이가 발생하면 변동 알림을 표시해야 한다
- **FR-006**: 사장님은 메뉴별 +/- 버튼 또는 직접 숫자 입력으로 판매량을 입력할 수 있어야 한다
- **FR-007**: 판매 입력 중에 매출/원가/순수익이 실시간으로 갱신되어야 한다
- **FR-008**: 판매 저장 시 그 시점의 메뉴 원가(레시피 × 각 재료의 평균 단가)를 판매 레코드에 스냅샷으로 함께 저장해야 한다 (역사적 마진 보존)
- **FR-009**: 자주 팔리는 메뉴는 지난 7일 판매량을 기준으로 자동 정렬되어야 한다
- **FR-010**: 0잔 입력된 메뉴는 판매 화면에서 자동 숨김 처리되어야 한다
- **FR-011**: 사장님은 7일 이내 미입력 날짜에 대해 소급 입력할 수 있어야 한다. 7일 초과 시 차단
- **FR-012**: 시스템은 영업일 그룹(월~목/금/주말) 최근가중 평균을 기본 anchor로 사용하고, 개별요일 표본 수에 따라 `count / (count + prior)` 방식으로 점진 보정한 사용량 + 거래처 리드타임 + 안전여유 1일을 반영해 재료 소진 예측을 산출해야 한다. 개별요일 반영 비중은 최대 85%로 제한한다
- **FR-013**: 시스템은 소진 예상 1~2일 전 발주 알림 푸시를 아침 9시에 발송해야 한다
- **FR-014**: 시스템은 마감 시간(밤 10시)에 판매 입력 독려 푸시를 발송해야 한다 (예: "오늘 판매 입력 1분이면 끝나요")
- **FR-015**: 시스템은 매주 월요일 오픈 전에 재고 실사 알림 푸시를 발송해야 한다
- **FR-016**: 재고 실사는 수량 보정만 수행하며 평균 단가를 변경하지 않는다
- **FR-017**: 시스템은 시스템 재고와 실재고의 차이를 "주간 손실액"으로 환산해 표시해야 한다
- **FR-018**: 가입 후 7일까지 모든 화면에 "데이터 수집 중" 안내를 표시한다 (콜드스타트)
- **FR-019**: 마진/순수익/마진율을 표시하는 모든 지점에 "재료 원가 기준 (이동평균법)" 라벨이 함께 노출되어야 한다 — 누락 시 출시 차단 사유
- **FR-020**: 어제 매출 비교는 "지난주 같은 요일 대비"로 표시한다 (전일 비교 금지)
- **FR-021**: 캘린더는 7×6 그리드로 매출 인텐시티 배경 + 매입(앰버)/누락(레드) 도트 + 매출 만원 단위 숫자를 셀별로 표시해야 한다
- **FR-022**: 캘린더 누락일 셀 탭 시 해당 날짜의 판매 입력 화면(소급 입력 모드)으로 이동해야 한다
- **FR-023**: 캘린더 월간 누적 카드는 매출/순수익/일평균/영업일수를 "재료 원가 기준" 라벨과 함께 표시해야 한다
- **FR-024**: 캘린더에서 미래 날짜·가입 이전 날짜·7일 초과 누락일은 입력 불가로 처리한다
- **FR-025**: 7일 평균 vs 30일 평균 차이가 ±20% 이상이면 사용량 급증/급감 배지를 표시해야 한다
- **FR-025a**: 예측 화면은 사용 가능한 데이터 일수, 개별요일 보정 비율, 신뢰도 레벨을 함께 표시해야 한다
- **FR-025b**: 예측 정확도 화면은 일반 MAPE 대신 WAPE(총 절대오차 ÷ 총 실제값), 절대오차, 과대/과소예측 방향, 원인 후보(데이터 부족, 특정 요일 오차 집중, 실제 판매 없음, 부족/과발주 위험)를 표시해야 한다
- **FR-025c**: 메뉴 예측 정확도는 평균 절대 수량오차를 사용자 화면에 “평균 N개 오차”로 표시해야 한다
- **FR-025d**: 매출 예측 정확도는 평균 절대 금액오차와 signed error를 사용해 미래 예측 범위(예상 N만±M만 또는 하한~상한)와 과거 “높게/낮게 예측” 문구를 표시해야 한다
- **FR-025e**: 재료 예측 정확도는 평균 일수오차와 과소예측일 수를 사용해 “보통 ±N일”, “빠르면 N일”, “부족위험일”을 표시해야 한다
- **FR-026**: 메뉴 옵션·토핑은 메뉴 옵션 그룹/옵션값으로 등록할 수 있어야 하며, 옵션 레시피와 선택률은 메뉴 수요 예측에서 재료 소요량으로 환산되어야 한다
- **FR-027**: 모든 화면은 모바일 우선 레이아웃이며 하단 탭 네비게이션은 5개(오늘 / 캘린더 / 판매 / 메뉴 / 재료)로 구성. 매입은 컨텍스트 진입(예: 재료 화면 또는 빠른 액션)
- **FR-028**: 재고 실사 입력 시점에 시스템 재고와 실재고 차이를 사용자에게 보여주고 보정 여부를 확인 받는다
- **FR-029**: 매입·실사 시 변경되는 평균 단가/재고량은 변동 이력 레코드로 기록한다 (재료 단가 이력)
- **FR-030**: 사용자는 7일 이내 저장된 Sale 레코드를 편집·삭제할 수 있어야 한다. 7일 초과 레코드는 잠금 처리되어 편집 불가
- **FR-031**: Sale 편집·삭제 시 모든 변경은 변경 이력으로 기록된다 (변경 일시, 편집 사유 선택 입력, 변경 전/후 항목 스냅샷)
- **FR-032**: Sale 편집 저장 시 그 시점의 메뉴 원가 스냅샷으로 재계산되어 저장된다. 이전 스냅샷은 변경 이력에 보존된다 (역사적 마진 보존 = 시간 경과에 따른 자동 재계산 금지이며, 사용자 명시 편집은 새 스냅샷 생성)
- **FR-033**: Sale 편집·삭제 시 차감된 재료 수량을 되돌리고 새 항목 기준으로 재차감한다 (재고 일관성 보장)
- **FR-034**: 사용자는 계정 설정에서 탈퇴를 신청할 수 있다. 탈퇴 신청 시점부터 30일간 grace period가 시작된다
- **FR-035**: Grace period 중 사용자 데이터는 보존되며, 로그인은 차단된다. 사용자는 별도 복구 경로(예: 동일 이메일 재인증)로 30일 이내에 계정을 복구할 수 있다
- **FR-036**: Grace period 30일 경과 시 사용자 본인 식별 정보 + 모든 도메인 데이터(매입·판매·메뉴·재료·재고 실사·이력 레코드 포함)는 영구 삭제된다 — 이후 복구 불가
- **FR-037**: 탈퇴 신청 시 사용자에게 grace period 정책과 영구 삭제 일자를 명시적으로 안내하고 확인을 받는다
- **FR-038**: 메뉴·재료·거래처 이름은 사용자 단위로 유일해야 한다 (활성·비활성 무관). 동일 이름 등록 시도 시 차단하고 기존 항목 안내
- **FR-039**: 데이터 동기화는 last-write-wins 정책을 따른다. 다중 디바이스 동시 편집은 가정하지 않으며, 충돌 감지·해결 로직은 1차 MVP에 포함하지 않는다. 마지막 저장이 서버 데이터를 덮어쓴다
- **FR-040**: 사용자는 가게 정보 등록·수정 시 정기휴무 요일을 선택할 수 있어야 한다 (월~일 중 복수 선택 가능, 0개 선택 시 365일 영업)
- **FR-041**: 시스템은 정기휴무 요일을 누락 카운트, 판매 입력 독려 푸시, 재고 실사 알림 발송에서 제외해야 한다
- **FR-042**: 정기휴무 요일은 소진 예측의 영업일 그룹/개별요일 최근가중 평균 산정에서 제외된다 (정상 영업일 기준 평균만 사용)
- **FR-043**: 캘린더는 정기휴무일을 회색 비활성으로 표시해야 한다 (가입일 이전 셀과 동일한 시각 패턴, 누락 카운트 미적용)
- **FR-044**: 정기휴무 요일 변경은 변경 시점 이후부터 적용되며 과거 데이터에는 영향을 주지 않는다 (과거 표시는 그 시점의 규칙 유지)
- **FR-045**: 정기휴무 요일에도 사용자가 명시적으로 그날 판매를 입력하면 정상 영업일로 인식되어 캘린더에 표시되고 누락 카운트·예측 산정에 포함된다 (예외 영업)

### Key Entities

- **User (사장님)**: 이메일, 가게이름, 가게유형(빙수카페/카페/디저트카페), 가입일, 정기휴무 요일(복수 가능, 기본값 없음 = 365일 영업), 탈퇴 신청일(선택), 영구 삭제 예정일(선택)
- **Ingredient (재료)**: 이름, 단위(g/ml/개), 현재 재고량, 현재 평균 단가, 유통기한(선택)
- **IngredientPriceHistory (재료 단가 이력)**: 재료 참조, 변경 일시, 직전 평균 단가, 신규 평균 단가, 변경 사유(매입/실사 보정)
- **Vendor (거래처)**: 이름, 리드타임(일)
- **PurchaseOrder (매입)**: 거래처 참조, 날짜, 항목 목록 [재료 참조, 수량, 금액]
- **Menu (메뉴)**: 이름, 판매가, 활성 여부
- **RecipeItem (레시피 항목)**: 메뉴 참조, 재료 참조, 사용량
- **MenuOptionGroup (메뉴 옵션 그룹)**: 메뉴 참조, 이름, 선택 방식(택1/추가), 필수 여부
- **MenuOptionValue (메뉴 옵션값)**: 옵션 그룹 참조, 이름, 기본 옵션 여부, 추가금, 옵션별 재료 사용량
- **Sale (판매)**: 날짜, 항목 목록 [메뉴 참조, 수량, **판매 시점 메뉴 원가 스냅샷**]
- **DailyStockCount (재고 실사)**: 날짜, 항목 목록 [재료 참조, 실재고량]
- **SaleEditHistory (판매 편집 이력)**: Sale 참조, 변경 일시, 변경 종류(편집/삭제), 편집 사유(선택), 변경 전 항목 스냅샷, 변경 후 항목 스냅샷

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사장님은 가입 후 5분 이내에 첫 가치를 경험한다 (메뉴 1개 이상 등록 + 첫 판매 입력 완료)
- **SC-002**: D7 리텐션 40% 이상 (가입 7일 후 활성 사용자 비율)
- **SC-003**: 일일 판매 입력률 60% 이상 (가입자 중 매일 입력하는 비율)
- **SC-004**: 주간 재고 실사 수행률 50% 이상
- **SC-005**: 마진/순수익/마진율 표기 누락 사례 0건 (모든 표시 지점에 "재료 원가 기준" 라벨 동반) — 출시 차단 사유
- **SC-006**: 재료·메뉴·매출 예측 정확도는 백테스트 화면에서 WAPE, 절대오차, 일수오차, 과대/과소 방향으로 추적 가능해야 하며, 재료 소진 위험은 “보통 ±N일 / 빠르면 N일” 단위로 해석 가능해야 한다
- **SC-007**: 페르소나 사용자 테스트에서 핵심 화면(판매 일괄 입력) 첫 입력 완료까지 소요 시간 5분 이내
- **SC-008**: 월 1회 NPS 측정에서 "친구 사장님께 추천하시겠어요?"에 7점 이상 응답 비율을 추적한다
- **SC-009**: 가중 이동 평균법 회계 정확성 — 30일 매입 데이터로 검증 시 공식 동등성을 만족한다 (수동 계산값과 시스템 산출값 일치)
- **SC-010**: 한 번 저장된 과거 매출의 마진은 시간이 지나도 변하지 않는다 (역사적 마진 보존)
- **SC-011**: 캘린더에서 누락일 발견 → 소급 입력 완료까지 소요 시간 1분 이내 (페르소나 테스트)
- **SC-012**: 가입 직후 빙수카페 템플릿으로 메뉴 8개 등록 완료까지 소요 시간 3분 이내

## Assumptions

- 사장님은 1인 운영 또는 본인 + 알바 1명 수준의 소규모 가게다
- 모바일 우선 사용. 데스크탑은 부가 채널이며 반응형으로 커버한다
- 레시피는 셋업 시 1회 등록하고 가격 변동 시 수정한다 (자주 변경되지 않음)
- 메뉴 옵션·토핑은 옵션 그룹/옵션값으로 관리하며, 선택률이 쌓이면 재료 소요량 예측에 반영한다
- 인터넷 연결은 안정적이라 가정한다 (오프라인 모드 미지원)
- 기존 POS·회계 시스템과의 연동은 없다
- 한국어 단일 언어 (다국어 미지원)
- 푸시 알림 시간(아침 9시 발주 알림 / 밤 10시 입력 독려)은 1차 MVP에서 고정값이며 사용자 변경은 미지원
- 재고 실사는 사용자가 자발적으로 입력하는 행위이며 미입력에 대한 강제는 없다 (알림만)
- 디자인 산출물은 `.claude/skills/easystock-design-system` 스킬을 단일 진실 공급원으로 참조한다 (헌법 Design Source)
- 시간대는 사용자 가게 기준 한국 표준시(KST) 단일 가정
- 사용자는 단일 디바이스 사용을 가정한다. 다중 디바이스 동시 편집은 1차 MVP 가정 외 (last-write-wins로 처리)

## Out of Scope (헌법 V 스코프 가드)

다음 항목은 1차 MVP에서 명시적으로 제외한다:

- 임대료·인건비를 포함한 순이익 계산
- OCR 영수증 인식
- POS 연동
- 자동 발주 메시지 발송 (1차는 수동 복사로 대체)
- 직원 권한관리·근태·인건비 자동 계산
- 계절성 자동 보정 (1년 데이터 누적 후 재논의)
- 결제·구독 (수익화 모델 미확정)
- 매입 직접 취소·환불 처리 (정정 매입으로만 보정)
- 다국어 지원
- 오프라인 모드
- 푸시 알림 시간의 사용자 커스터마이징
- 데이터 export (CSV/PDF/ZIP) — 1차 MVP 미지원, 2차 검토
- 멀티 디바이스 Realtime 동기화·충돌 감지 — last-write-wins로 시작, 2차 검토
